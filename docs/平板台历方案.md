# 小米平板「考公台历」方案

> 状态：**方案稿（未开工）**。本文只写「要建什么、怎么建、为什么这么定」，

## 一、目标

在独立仓库 `gongkao-app` 里建一个 **Flutter 工程**，打成**真安卓 apk**，
装到小米**平板**（主）与安卓**手机**（副）上当**全屏常亮台历 + 考试倒计时**，
版面上轮播考公内容。

一句话验收：平板横屏放着，不熄屏，白天能看清日期和倒计时，右半屏每半分钟换一条
行测常识 / 高频成语 / 时政热词；手机上竖屏打开是同一份内容的单栏版；点一下可切到
番茄钟，跑 25 分钟专注循环并可放背景白噪音。

## 二、裁定（用户已定，改动需用户重裁）

### 选型依据：为什么是 Flutter（性能 × 跨端）

用户在「性能 + 跨端」两个维度上比较后选定 Flutter。要点记录如下，避免日后重翻。

**性能**（冷启动 / 内存 / 动画帧率 / apk 体积）：

| 方案 | 冷启动 | 内存 | 动画 | 体积 | 根因 |
|---|---|---|---|---|---|
| 原生 Compose | 最快 | 最低 | 满帧 | 最小(几 MB) | 直编 Android 字节码 |
| **Flutter** | 略慢于原生 | 中 | 满帧且稳 | 中(十几 MB) | 自带引擎，AOT 编机器码，自绘 |
| RN / Expo | 最慢 | 最高 | 好(Reanimated 走 UI 线程) | 中偏大 | JS 引擎 + 桥，双运行时 |
| Capacitor / PWA | 慢 | 高 | 受 WebView 限 | 大 | 依赖系统 WebView |

纯性能排序：**原生 Compose > Flutter > RN > Capacitor/PWA**。

**跨端**：

| 方案 | 安卓 | iOS | 桌面 | Web |
|---|---|---|---|---|
| **Flutter** | ✅ | ✅ | ✅ | ✅ |
| RN / Expo | ✅ | ✅ | 弱 | ✅ |
| 原生 Compose | ✅ | ❌/实验 | 实验 | 实验 |
| Capacitor / PWA | ✅ | ✅ | ✅ | ✅ |

只有 **Flutter 与 Capacitor** 真正兑现跨端；而性能上 Flutter 远胜 Capacitor。
**Flutter 是「性能接近原生 + 全平台跨端」的唯一同时满足者**——这正是其存在意义。

**取舍坦白**：

- 台历本身是静态展示，四种方案都**性能过剩**，差异在本 app 上几乎感知不到
  （唯 RN 冷启动慢半拍）。选 Flutter 是**为平板将来可能的更大野心**买单（重动效、
  多端），而非本 app 即时收益。
- 被否方案：PWA（非 apk，用户已否）；Capacitor 套壳主站（动画弱、绑死主站发布节奏）；
  原生 Compose（性能第一但跨端残，且要写 Kotlin）；RN/Expo（冷启动与内存最弱）。
  备选留存：若日后放弃跨端只要安卓，**原生 Compose** 是性能更优的替代。

## 三、数据方案

### 只取三份，不搬整个题库

`gongkao/data/` 下的行测真题（`xingce/*.json`，单卷即数百 KB、合计几十 MB）**不适合**
台历轮播——台历要的是「一句话能读完的卡片」。故只取：

| 源文件（在 `gongkao/data/`） | 大小 | 卡片类型 | 字段 |
|---|---|---|---|
| `common-sense.json` | 22K | 行测常识 | `term` / `meaning` / `distinction` / `example` |
| `idioms.json` | 159K | 高频成语 | `word` / `meaning` / `distinction` / `example` |
| `politics-hot.json` | 11K | 时政热词 | `term` / `meaning` / `distinction` / `example` |

三份结构相近（除成语用 `word` 外，其余用 `term`），归一化后统一成：

```dart
class CardItem {
  final String kind;      // '常识' | '成语' | '时政'
  final String? group;    // 常识的 group(法律/科技…)、时政的 group(重要会议…)
  final String title;     // term 或 word
  final String body;      // meaning
  final String? extra;    // distinction（辨析），可能缺失
  final String? example;  // example，可能缺失
}
```

> 排除 `guifan-terms.json`（524K，申论规范词）的理由：其字段为 `theme` / `term` / `example`，
> **没有释义（meaning）**——只有词与用例，单独成卡信息不全，故不取。

### 农历

日期区要显示农历，用 **`lunar`**（pub.dev 的 `lunar`，6tail 出品，纯 Dart、**无第三方依赖**，
MIT 许可）：`Lunar.fromDate(DateTime.now())` 取 `.getMonthInChinese()` / `.getDayInChinese()`
拼出「九月初二」。若日后要节气/干支/生肖，同库也有，无需换库。

### 镜像脚本

`scripts/sync_data.mjs`（Node，纯脚本、不进 Flutter 依赖）：从 `../gongkao/data/`
（相对本仓）读三份 JSON → 归一化 → 写入本仓 `assets/data/*.json`，Flutter 侧以
`rootBundle.loadString('assets/data/xxx.json')` 读取。可重复执行以刷新内容。

- 路径参数化：接受 `--src=<主仓data目录>`，默认 `../gongkao/data`，便于主仓改名/挪位。
- 产物**进 git**：内容是 apk 的主体，且主仓 `data/` 与源码分离（主仓约定 `data/` 不进
  `src/`），本仓镜像到 `assets/` 不违反该约定。

### 版权口径

三份内容的版权归各自权利人。本 apk **仅个人学习自用、不单独分发、不商用**。
同口径写入 `README.md` 顶部。

## 四、页面设计（自适应：平板横屏两栏 / 手机竖屏单栏）

### 平板（宽屏 · 横屏两栏）

```
┌───────────────────────────────────────────────────────────┐
│                                            2026年10月12日  │
│   10月                                            星期日    │
│    12          ┌──────────────────────────────┐            │
│  星期日         │ 行测常识 · 法律               │            │
│                │ 全国人民代表大会              │            │
│  距 2027 国考    │ 最高国家权力机关。行使国家立… │            │
│  还有 47 天     │ ────────────────────────      │            │
│                │ 与「全国人大常委会」区分：…    │            │
│                └──────────────────────────────┘            │
│  已过 132 天  ·  公元 2026 · 农历九月初二                    │
└───────────────────────────────────────────────────────────┘
```

### 手机（窄屏 · 竖屏单栏）

```
┌──────────────────────┐
│    10月12日  星期日    │
│    农历九月初二        │
│                      │
│        12            │
│                      │
│   距 2027 国考        │
│   还有 47 天          │
│  ─────────────────   │
│  ┌────────────────┐  │
│  │ 行测常识 · 法律  │  │
│  │ 全国人民代表大会 │  │
│  │ 最高国家权力机…  │  │
│  │ ──────────────  │  │
│  │ 与「全国人大常…  │  │
│  └────────────────┘  │
│   已过 132 天         │
└──────────────────────┘
```

- **断点**：用 `LayoutBuilder` 取 `constraints.maxWidth`。`>= 720dp` 走两栏（平板），
  否则走单栏（手机）。720dp 是「平板与手机分界」的常用阈值（也贴合小米平板的最小宽度），
  具体值放在 `config.dart` 便于调。
- **左区/上区「日期区」**：特大字号日期数字 + 月份 + 星期 + **农历（如「九月初二」）**；
  下方倒计时两行（`距 <考试名> 还有 N 天`，`已过 M 天`）。
- **右区/下区「内容区」**：内容卡轮播，间隔（默认 30s）在 config 里；左上角 `kind` 标签
  按类型着色（常识 / 成语 / 时政 三色），题名加粗、正文常规、辨析与例证弱化色。
- **轮播顺序**：三类混排（按 kind 轮转取样，避免连续同类型），而非顺序遍历。
- **空内容兜底**：若 `assets/data/` 缺文件或某类为空，只显示日期区，内容区出一句提示
  文案（不崩溃、不空白）。
- **换卡动效**：`AnimationController` + `SlideTransition`/`FadeTransition`（Flutter
  自绘、满帧），后续可升级 3D 翻转、数字滚动等——这是选 Flutter 预留的能力。
- **常亮**：`wakelock_plus` 的 `WakelockPlus.enable()`，页面挂载期间不熄屏。
- **沉浸全屏**：`SystemChrome.setEnabledSystemUIMode(SystemUiMode.immersiveSticky)`
  隐藏状态栏与导航栏。
- **屏幕方向**：**不锁死单一方向**，由运行时代码按屏幕宽度设 preferred orientations
  与布局：宽屏（平板）横屏两栏，窄屏（手机）竖屏单栏；`AndroidManifest.xml` 不写死
  `screenOrientation`。（`main.dart` 负责初始化，见 §五。）
- **日/夜**：跟随系统深色（`ThemeMode.system`）；深色下压低整体亮度与对比，夜间不刺眼。
- **无操作（台历界面）**：台历界面不依赖点按，插上电就是台历；唯一手势是切到番茄钟。

### 番茄钟界面（宽/窄屏通用，单栏居中）

```
┌─────────────────────────────────────────┐
│  ← 返回台历                              │
│                                         │
│              专注中 · 第 2 轮             │
│                                         │
│              24 : 37                    │   ← 特大等宽数字
│         ▓▓▓▓▓▓▓▓░░░░░░░░░░░░            │   ← 进度环/条
│                                         │
│        [ 暂停 ]   [ 重置 ]   [ 跳过 ]     │
│                                         │
│   🌧 雨声    音量 ──────●────            │   ← 背景音（框架）
└─────────────────────────────────────────┘
```

- **界面切换**：台历右上角一个不打扰的「番茄钟」入口 → 全屏番茄钟；番茄钟左上角
  「返回台历」切回。**两屏互不干扰**，台历仍是默认常亮展示。
- **计时状态机**：`专注(25) → 短休(5) → …×4 → 长休(15) → 循环`。时长全部取自
  `config.dart`（`pomodoroMinutes` / `shortBreakMinutes` / `longBreakMinutes` /
  `roundsPerLongBreak`），改配置即改节奏。
- **操作**：开始 / 暂停 / 重置 / 跳过。跨屏或切到后台不打断计时（用 `DateTime` 记目标
  时刻、每帧算剩余，而非累加 `Timer`，避免后台被节流后走慢）。
- **阶段提醒**：一段结束用**短振动/提示音**（可选、可在 config 关）。不做系统通知栏
  （那要 `audio_service`/后台服务，超出个人自用所需）。
- **与常亮的联动**：番茄钟运行时同样保持常亮（复用 `wakelock_plus`）。

### 背景音（本次只搭框架，素材后补）

- **库**：`audioplayers`。理由：一行 `ReleaseMode.loop` 即循环、`setVolume()` 调音量、
  直接播 assets，无需后台服务/通知栏（我们不做后台播放）。
- **声音种类（占位，待用户后定/后补素材）**：拟内置 3–4 条循环白噪音，如
  雨声 / 海浪 / 咖啡馆 / 白噪音。素材放 `assets/audio/*.mp3|ogg`，每条 1–5 分钟、
  **须无缝循环**（首尾可衔接，否则循环处有断点）。
- **本次交付**：播放/暂停、音量滑块、选音源的下拉（选项来自 `config.dart` 的列表）；
  **素材未就位时列表为空、播放器静默禁用**，不报错。
- **与番茄钟的关系**：背景音挂在番茄钟界面（见上图右下）；台历界面不放背景音。
- **版权**：素材必须**可商用/CC0**（用户后补时注意），不随仓库分发有版权风险的音频。

## 六、出 apk 的前置与步骤

### 前置（本机当前均未安装）

本机现无 Java、无 Android SDK、无 Gradle、无 Flutter。需先装：

1. **Flutter SDK**（`brew install --cask flutter` 或官方 tar；约 1–2 GB）。
   装后 `flutter doctor --android-licenses`。
2. **JDK 17**：`brew install --cask temurin@17`。
3. **Android SDK commandline-tools**，然后
   `sdkmanager "platform-tools" "build-tools;34.0.0" "platforms;android-34"`
   并接受许可。
4. 环境变量：`ANDROID_HOME`、`PATH` 加 `platform-tools`；`flutter doctor` 全绿。
   合计约 5–7 GB 磁盘（本机当前空余 741 GB，充足）。

### 步骤

> **注意：先 create 再放文档。** `flutter create` 要求目标目录为空或已是 Flutter 工程，
> 而本仓 `README.md` / `docs/` 会让它拒绝或试图覆盖。**开工顺序**：在空目录里先
> `flutter create`，再把 `README.md` / `docs/` 加进来；若目录已被占，先临时移出文档、
> create 完再移回。

```bash
# 1. 建工程（在空目录 gongkao-app/ 内执行）
flutter create --org com.gongkao --project-name gongkao_pad .
#   包名 = com.gongkao.gongkao_pad

# 2. 装依赖（写入 pubspec.yaml）
flutter pub add wakelock_plus lunar audioplayers

# 3. 镜像内容
node scripts/sync_data.mjs            # 或 --src=/path/to/gongkao/data

# 4. 调试（连平板/手机/模拟器）
flutter run

# 5. 出 apk
flutter build apk --release
#   产物：build/app/outputs/flutter-apk/app-release.apk
```

> 首次出 release apk 用 debug 签名（可直接侧载）。若要正式签名，另配
> `android/key.properties` + `signingConfigs`（本方案暂不涉及，个人自用 debug 签名足够）。
> 一个 apk 同时含两套版式，**平板与手机装同一个包**，运行时按屏幕宽度自适应。

### 装到设备

任选一种把 `app-release.apk` 送到设备：

- **USB**：`adb install -r build/app/outputs/flutter-apk/app-release.apk`（需 `platform-tools`）。
- **传文件**：通过微信/网盘/数据线把 apk 复制到设备，点开安装。

设备侧：设置 → 允许「安装未知来源应用」→ 安装 → 打开即台历。
建议在设备上开启「开发者选项 → 充电时保持唤醒」双保险。

## 七、AI 规划（含登录主站 + 读用户数据）

> 本节是文档中**唯一引入联网、登录、跨仓耦合**的部分。它推翻了初版「内容离线内置、
> 不自建后端、不做云同步」的定位——用户裁定走 **B 方案（登录主站、读用户数据）**。
> 读代码确认的主站事实见下，改动请同步本节。

### 7.1 定位变更（重要）

app 定位由「纯离线台历」变为**混合**：

| 能力 | 是否需要联网 | 说明 |
|---|---|---|
| 台历 / 倒计时 / 内容轮播 / 番茄钟 / 背景音 | **否** | 全部本地，断网照用 |
| AI 规划 | **是** | 需调大模型 API |
| 登录主站 / 读错题与做题记录 | **是** | 需 Supabase 鉴权 + 主站反代 |

**降级原则**：无网或未登录时，台历等本地功能不受影响；AI 规划入口提示「需联网/需登录」。

### 7.2 复刻登录（读代码所得，必须照做）

主站 `gongkao` 的登录事实（`src/stores/authStore.ts`、`src/lib/supabase.ts`）：

- **Supabase Auth**（邮箱密码 / Magic Link），客户端用 **anon key + RLS**，`session` 由
  supabase-js 持久化（web 存 localStorage，**Flutter 侧改存 `shared_preferences`**）。
- **base URL 必须走自域反代**：`VITE_SUPABASE_URL=https://read.zhangdapao.com/sb`。
  原因（主仓 AGENTS.md 踩坑）：`*.supabase.co` 在大陆被**按 SNI 在 TLS 阶段 reset**，直连
  登录/云同步全挂；反代由 Vercel 边缘发起方才可用。**apk 同样只能走这个反代**，不能直连。
  → Flutter 用 supabase-dart / gotrue-dart，baseUrl 填 `https://read.zhangdapao.com/sb`。
- **anon key**：主站放在 `VITE_SUPABASE_ANON_KEY`（可公开、配合 RLS）。apk 若公开仓库，
  anon key 可入库（它本来就会暴露到浏览器）；**但 service_role key 绝不能进**。

> **红线**：anon key 可公开、RLS 保证只读本人数据；此约定依赖主站 RLS 策略已全部就位
> （`sql/sync.sql` + `sql/xingce.sql` 已为每张表 enable RLS + `auth.uid() = user_id`）。

### 7.3 读哪些用户数据（喂给 AI 的输入）

主站用户数据在 Supabase 各表（见 `sql/sync.sql`、`sql/xingce.sql`），apk 直连反代后按
RLS 可读**本人**行：

| 表 | 内容 | 对规划的用处 |
|---|---|---|
| `xg_answers` | 行测作答 `{paperId,qIdx,picked,correct,seconds,origin,updatedAt}` | **算各模块正确率/薄弱项**（主输入） |
| `xg_notes` | 行测每题笔记 | 参考难点 |
| `exam_study` | 真题 traces/marks | 申论作答痕迹（参考） |
| `article_study` / `annotations` | 文章精读与摘录 | 阅读量参考 |
| `learning_events` | 学习事件流（append-only） | **学习频次/时长趋势** |
| `user_ai_config` | `{baseUrl,model,apiKey}` | **可复用主站 AI 配置**（省得重填） |

**规划输入构造**（本地聚合后送模型，不把整库丢给 AI）：

- 从 `xg_answers` 按 `paperId` 前缀（模块/年份）聚合出「各模块近期正确率、平均耗时」；
- 从 `learning_events` 聚合「近 7/30 天学习次数」；
- 叠加 **app 本地数据**：番茄钟完成轮数、勾选清单完成情况；
- 叠加**用户手填目标**：目标考试、剩余天数、每天可用时长、自述弱项。

> 隐私：这些是用户自己的数据，经反代读回本机后**在本机构造 prompt**，只把**聚合统计**
> 与手填目标发给用户在 7.4 配的模型端点；不上传原始错题明细（除非用户显式选「附带错题」）。

### 7.4 AI 配置（与主站的关系）

- **默认继承主站 `user_ai_config`**：登录后读该表，`baseUrl/model/apiKey` 直接可用
  （省去重填 key，与主站「换设备免重填」一致）。
- **本地可覆盖**：app 内留一个 AI 设置页，允许改 baseUrl/model/apiKey，存
  `shared_preferences`。优先级：本机设置 > 主站 `user_ai_config` > 无（提示未配置）。
- **调用方式差异（重要）**：主站 AI 请求经其服务端 `/api/ai` 纯转发（key 不直连第三方）；
  **apk 没有这个服务端**，只能**用配置的 baseUrl 直连**（OpenAI 兼容 `/chat/completions`）。
  代价：apk 直接持有 key（个人自用可接受）；若 key 泄露风险敏感，可改为只经
  `read.zhangdapao.com/api/ai` 转发（需主站开放该端点给 apk，属额外改动，暂不做）。

### 7.5 规划产出与存放

- **形态**：可勾选的**每日/每周任务清单**。每条 `{date, title, note?, done}`。
- **存放**：本地 `shared_preferences`（JSON）。**本期不回写主站**（不做「清单也上云」）。
- **交互**：生成 → 展示清单 → 逐条勾选 → 可「重新生成」（覆盖前提示将丢失勾选状态）。
- **不做**：不做打卡统计表、不做跨设备同步清单（如需，另开需求）。

### 7.6 界面

```
┌─────────────────────────────────────────┐
│  ← 返回台历           AI 规划    [重新生成]│
│  未登录时：本页提示「登录后可读你的做题数据」 │
│  未配 key：提示「去设置里填 AI 配置」       │
│ ─────────────────────────────────────── │
│  备考目标：2027 国考 · 行测偏弱 · 每天 2h   │
│ ─────────────────────────────────────── │
│  ☐ 10/12  资料分析专项 20 题（正确率偏低）  │
│  ☑ 10/12  言语理解 15 题                   │
│  ☐ 10/13  复盘昨日错题 …                   │
└─────────────────────────────────────────┘
```

- 入口：台历右上角第二个入口（与「番茄钟」并列）。
- 三态：**未登录** / **未配置 AI** / **正常**，各自给明确引导，不静默失败。
- 生成是**流式**还是**一次性**：先用一次性（简单、易处理错误）；流式列为可选优化。

### 7.7 依赖与风险

- 新增 Flutter 依赖：`supabase_flutter`（含 gotrue，认证 + PostgREST 查询）、
  `shared_preferences`（本地清单/设置）、`http` 或 `dio`（调模型端点，及读主站公开 API）。
- **Android 权限**：`INTERNET`（联网必备）。
- **风险**：
  - **反代可用性**：AI 与登录都依赖 `read.zhangdapao.com`，它挂了 app 的联网功能全挂
    （本地功能不受影响）。
  - **Cookie/会话**：Flutter 无浏览器同源限制，走 supabase-dart 自带 token 续期；注意
    与 web 端**不共享**登录态（各存各的）。
  - **模型费用**：直连用户的 key，调用量由用户自己控制。
- **建议**：把「登录 + 读数据 + AI 规划」作为**第二阶段**（Phase 2）实现，Phase 1 先交付
  纯离线台历 + 番茄钟 + 背景音（§四–§六）。见 §十 实施顺序。

- 不在未获用户批准前安装 Flutter SDK / Android SDK，不出包。

## 十、实施顺序

分两阶段，**Phase 1 先交付可用的离线台历**，AI 相关的复杂度独立成 Phase 2：

- **Phase 1（离线）**：工程骨架 → 数据镜像 → 台历页（自适应）→ 农历 → 番茄钟 → 背景音框架
  → 出 apk 装机。此阶段**不需要登录、不需要联网**。
- **Phase 2（联网）**：登录（supabase_flutter + 自域反代）→ 读用户数据聚合 →
  AI 配置（继承主站 + 本地覆盖）→ 生成可勾选规划清单。
